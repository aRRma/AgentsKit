Повторную проверку отсекают флаг повтора и маркер коммита

Второй раз ход не блокируется

Если stdin перенаправлен, хук читает JSON и при stop_hook_active: true сразу возвращает 0. Без этого агент не смог бы остановиться и задать вопрос (:11-17). Битый JSON хук молча игнорирует и проверяет дальше (:19).

главное

Маркер проверенного коммита

Маркер — файл verified-head внутри git, его путь даёт git rev-parse --git-path (:30). Проверка пропускается, если дерево чистое и HEAD совпадает с маркером (:34). После успеха маркер пишется, только если дерево чистое (:44).

Строгая полная сборка

dotnet build --no-incremental -warnaserror -v q: любое предупреждение валит шаг, сборка идёт с нуля (:36).

Тесты без пересборки, с фильтром

dotnet test --no-build; второй аргумент уходит в --filter (:39-41). В примере настройки — "Category!=Slow" (settings.example.json:37).

Неочевидное: что легко упустить при настройке

настройка

Путь к решению — от корня репозитория

Хук переходит в корень репозитория (:26) и только потом ищет файл (:28). Неверный путь даёт код 1, и ход завершается без проверки.

правки

Пока есть незакоммиченные правки, проверка идёт на каждом Stop

При грязном дереве условие на :34 не выполняется, а маркер не пишется (:44). Каждое завершение хода стоит полной сборки и тестов

Вне репозитория проверки нет

Если git rev-parse --show-toplevel вернул не 0, хук возвращает 0 (:25).

При коде 2 stdout не пустой

В stdout идёт строка «Stop-check: не прошёл шаг «…»». Комментарий: без неё Claude Code «может счесть код 2 ошибкой самого хука» (:56-57).

Длинный вывод обрезается с начала

В stderr попадают последние 6000 символов stdout и stderr шага (:54-55). Начало вывода теряется.

stderr читается параллельно с stdout

ReadToEndAsync для stderr, затем синхронно stdout (:72-73). Так процесс не зависнет на полном буфере stderr
