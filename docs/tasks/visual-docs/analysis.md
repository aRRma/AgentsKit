# Анализ: графическая документация в HTML

## Задача

Скилл набора arrma-kit, который по команде делает одну наглядную HTML-страницу: пояснение при анализе проблемы или фичи, результат этапа, результат всей задачи или разбор кода. На странице можно ответить на вопросы и сохранить ответы рядом с ней, а агент потом их прочитает.

### Playwright MCP

- По `file://` страницу не открывает. Проверено: `browser_navigate` вернул «Access to "file:" protocol is blocked». Снять запрет можно только флагом `--allow-unrestricted-file-access` в конфиге плагина — README microsoft/playwright-mcp.
- **Сервер не нужен.** Playwright сам отдаёт файл с диска по выдуманному адресу. Проверено на `GUIDE.html`: `browser_run_code_unsafe` с `page.route('http://visual.local/**', r => r.fulfill({ path: '<файл>' }))`, затем `page.goto('http://visual.local/GUIDE.html')` вернул заголовок «arrma-kit: шпаргалка». Повторный `browser_navigate` по тому же адресу снова загрузил страницу — маршрут живёт, пока открыта вкладка, а файл читается заново при каждой загрузке.
- Адрес должен быть `http://localhost:<порт>`, а не выдуманный домен. Проверено тем же `page.route`: на `http://visual.local` страница вывела `secure=false save=undefined`, на `http://localhost:65000` — `secure=true save=function`. Сервера на порту нет, ответ подставляет маршрут.
- Нет своего процесса, порта и правок конфига — это закрывает R13. Для R12 остаётся браузер Playwright: он с постоянным профилем, а профиль может держать только один браузер («A persistent profile can only be used by one browser instance at a time», README `@playwright/mcp`); окно с интерфейсом само не закрывается («never for headed ones»). Поэтому браузер закрывать в конце проверки всегда, и при ошибке тоже.
- Playwright MCP пишет снимки в `.playwright-mcp/` в корне проекта. Проверено: папка появлялась после `browser_navigate`. После одного `browser_run_code_unsafe` её не было.
- По умолчанию браузер открывается с окном: «headed by default» в README.

### Сохранение ответов в браузере (MDN, Chrome docs, WICG — по отчёту субагента)

- File System Access API в Chrome на странице `file://` есть. Проверено: headless Chrome с `--dump-dom` на пробной странице вывел `secure=true saveFilePicker=function directoryPicker=function`. Само окно выбора файла не проверено: нужен клик человека.
- В `showSaveFilePicker` задаются `suggestedName` и `id`. По `id` Chrome запоминает последнюю папку. Путь к папке задать нельзя, только известные папки или ранее полученный файл.
- После первого выбора файла вкладка пишет в него без окна, пока открыта. После перезагрузки или для новой страницы окно выбора откроется снова, в последней папке для этого `id`.
- `localStorage` у всех страниц `file://` в Chrome общий. Проверено: страница `a.html` записала значение, страница `sub/b.html` из другой папки прочитала его, `origin=file://`. Ключ должен включать путь страницы.
- В Яндекс Браузере 26.10 API есть и пишет в файл; повторное сохранение идёт в тот же файл без окна (ручная проверка, Q1). Где API нет (Firefox, Safari — MDN BCD: `version_added: false`), запасной путь — скачивание через Blob и `<a download>` в «Загрузки».

## Что менять

Один скилл `arrma-visual` с четырьмя режимами. Правила вида, проверки и сохранения у режимов общие, разные только разделы страницы. Несколько скиллов повторили бы общие правила (R5).

1. **`skills/arrma-visual/SKILL.md`** — без `context: fork`, на модели сессии, `disable-model-invocation: true` (R9).
   - **Режим** по аргументу: `этап N`, `задача`, `код <что>`, иначе — анализ темы или вопроса.
   - **Уточнение** (R10): одно сообщение — режим, тема, разделы и схемы. Ждать ответа.
   - **Источники:** файлы задачи, переписка, код. Каждое утверждение о коде с `file:line`. Чего нет в источниках, на страницу не идёт. Догадку помечать.
   - **Вид:**
     - первый экран — вывод одной фразой и главная схема;
     - заголовки — выводы, а не темы;
     - форма — по содержанию: поток и этапы — SVG; карточки и хронология — сетка; много строк — таблица с метками;
     - не больше 9 узлов и 12 стрелок; если таблица скажет то же самое, рисуем таблицу;
     - один акцентный цвет; смысл несёт не только цвет.
   - **Файл:** один `.html` в `<папка задачи>/visual/` (R11); вне задачи — в `docs/visual/` (Q2). CSS, SVG и JS внутри, без внешних запросов. Светлая и тёмная тема.

## Риски и неизвестное

- `browser_run_code_unsafe` — «RCE-equivalent» по описанию инструмента: выполняет код в процессе Playwright. Скилл даёт ему только фиксированный шаблон с путём к странице.
- Принимает ли `allowed-tools` скилла инструменты MCP — не проверено. Если нет, разрешения на Playwright придётся добавить в настройки, иначе проверка будет спрашивать подтверждения.
- Окно «Сохранить как» открывается при первом сохранении каждой страницы и после перезагрузки вкладки. Путь задать нельзя: окно откроется в последней папке для этого `id`, и для страницы из другой задачи папку придётся выбрать заново.
- Окно сохранения может открыться не в папке страницы (так было в Q1): ответы лягут не туда. Агент ищет файл и в папке задачи, и в «Загрузках».
- Окно сохранения Playwright пройти не может: проверка сохранения ограничена функцией сборки ответов.
- Качество SVG зависит от модели. Проверка Playwright ловит наложения и обрезку, но не неверный смысл. Нужны `file:line` и пометка догадок.
