# Требования: графическая документация в HTML

## Обязательно
R1. Новый скилл, «кторый просит ИИ агента в claude code создать графичекую документацию в виде html страницы».
R2. Документация может быть «по этапу, по вопросу из обсуждению или по все задаче. то есть вызываться в разных случаях».
R3. Страница «должна графически понятно и легкочитаемо отображать сложные вещи из диалога».
R4. Проанализировать подобные скиллы в сети, «чтобы изучить и взять из них лучшее или протестировать тут»; «проанализируй лучшие скиллы и реши что мы можем реализовать у себя».
R5. «возможно это будет несколько скиллоа на разные случаи жизни» — число скиллов решает анализ.
R6. Агент создаёт, проверяет и улучшает страницу через Playwright MCP.
R7. Пользователь открывает готовую страницу сам «в любом браузере», в блоках вопросов выбирает ответ или пишет свой и сохраняет кнопкой «Сохранить» (в блоке вопросов или у каждого вопроса).
R8. Пользователь пишет в чат, что закончил, и агент сам читает сохранённые ответы.
R9. Скилл вызывается «только по команде».
R10. Перед созданием страницы агент «уточнит на всякий случай что отобразить в визуализации».
R11. Страницы лежат в папке задачи; ответы сохраняются «в папку где лежит страница».
R12. Частые запуски не оставляют зависших процессов: «между частыми запусками не будет проблема с зависшими серверами? … Надо продумать».
R13. Проверка страницы — «максимально автономно на этой машине», без ручных действий пользователя.

## Ограничения
C1. Скилл в стиле набора arrma-kit: папка `skills/arrma-*/SKILL.md`, текст на русском, без новых зависимостей (пакетов) без согласия пользователя.

## Вне рамок
X1. Установка чужих скиллов и плагинов без согласия пользователя.
X2. Разбор PR: «PR не нужен точно».
